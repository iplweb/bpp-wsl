# BPP dla Windows (WSL) — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jeden `BPP-Setup.exe`, który na Windowsie x64 instaluje (w razie potrzeby) WSL, importuje własną dystrybucję Debian + Docker CE, pobiera obrazy BPP, generuje fałszywy certyfikat i uruchamia czystą instancję BPP z kreatorem pod `https://<localhost|IP>:8443/`, z ikonką w zasobniku.

**Architecture:** Trzy warstwy. (1) `distro/` — rootfs Debiana z dockerem i `/opt/bpp` (compose 7 usług, własny nginx, `bpp-ctl` w bashu mówiący JSON-em). (2) `installer/` — rozwiązanie .NET: `BPP.Core` (czysta logika, testowalna na Linuksie/macOS), `BPP.Windows` (wywołania wsl/netsh/rejestr), `BPP.Tray` → `BPP.exe`, `BPP.Setup` → `BPP-Setup.exe`, `BPP.Pack` (dokleja ładunek). (3) `build/` — skrypty budowania; .NET SDK natywnie z Homebrew, rootfs i testy bashowe przez Dockera.

**Tech Stack:** Debian trixie amd64, systemd, docker-ce + compose plugin, bash, jq, openssl, bats; nginx (oficjalny obraz); .NET 10 LTS WinForms, xUnit — SDK z `brew install --cask dotnet-sdk` (macOS arm64, cross-target `win-x64`); Docker/buildx na macOS (OrbStack, emulacja amd64).

**Spec:** `docs/superpowers/specs/2026-10-18-bpp-wsl-design.md`

## Global Constraints

- Port **8443** stały, tylko HTTPS; `webserver` publikuje wyłącznie `8443:443`.
- 7 usług: `dbserver`, `redis`, `appserver`, `workerserver`, `celerybeat`, `denorm-queue`, `webserver`. Bez authservera, pgbouncera, monitoringu, backupów.
- Wszystkie usługi `restart: unless-stopped`.
- Limity pamięci: dbserver 1g, appserver 1536m, workerserver 1g (`CELERY_WORKER_CONCURRENCY_PERCENT=25`), redis 256m (`--maxmemory 200mb`), celerybeat 256m, denorm-queue 256m, webserver 128m.
- Obrazy BPP przypięte do tagu podanego przy budowie (`BPP_IMAGE_TAG`, wymagany parametr builda; brak domyślnego `latest`).
- `postgres:18.4` (domyślna wersja nowych instalacji w `bpp-deploy/scripts/init-configs.sh`), `PGDATA=/var/lib/postgresql/data`, `POSTGRES_INITDB_ARGS="--locale-provider=icu --icu-locale=pl-PL"`, `redis:8.6.2`, `nginx:1.28` (przypięte).
- Bez HSTS: nginx nie dodaje nagłówka i robi `proxy_hide_header Strict-Transport-Security`.
- nginx przekazuje `Host $http_host` (z portem).
- Hosty: `localhost` + IPv4 Windowsa; ≥1 adres LAN → `DJANGO_BPP_HOSTNAMES=localhost,<ip…>`, brak → `DJANGO_BPP_HOSTNAME=localhost`; nigdy oba. `DJANGO_BPP_CSRF_EXTRA_ORIGINS` = `https://<host>:8443` dla każdego hosta.
- Certyfikat self-signed RSA 2048, ważny 3650 dni, SAN: `DNS:localhost`, `IP:127.0.0.1`, `IP:<każdy IP>`.
- `.wslconfig` nietknięty. Dystrybucja nazywa się `BPP`, dysk w `%LOCALAPPDATA%\BPP\wsl`, program w `%LOCALAPPDATA%\Programs\BPP\BPP.exe`, wpis odinstalowania w `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\BPP`.
- Manifest obu exe: `asInvoker`. UAC wyłącznie przez `BPP.exe --elevated <zadanie> <args>` (zadania: `enable-wsl`, `firewall <ścieżka>`, `remove-firewall`), ścieżki zawsze bezwzględne w argumentach.
- Reguła zapory: nazwa `BPP (8443)`, `dir=in action=allow program=<ścieżka> protocol=TCP localport=8443 profile=any`.
- Preflight: odmowa przy RAM < 8 GiB, wolnym dysku < 25 GiB, architekturze ≠ x64, zajętym porcie 8443.
- Teksty UI po polsku.
- .NET 10 zamiast 8 ze specu (8 traci wsparcie 2026-11-10) — jedyna świadoma zmiana względem specu.

## Review Focus

1. **Ponowne `bpp-ctl init` po nieudanym pobieraniu** — nie może wylosować nowego hasła DB (wolumen postgresa ma stare) → test w Task 4.
2. **`bpp-ctl start` z tą samą listą hostów** — nie odtwarza kontenerów ani certyfikatu → test w Task 4 i E2E w Task 5.
3. **Brak sieci / tylko loopback** — lista hostów = sam `localhost`, tryb jednohostowy poprawny dla Django → testy w Task 1 i Task 7.
4. **Odmowa UAC** — `Elevation.Run` zwraca `false` (Win32 1223), instalator idzie dalej z dostępem tylko lokalnym → test gałęzi w `InstallerPlan` (Task 12) i checklista (Task 13).
5. **Wyjście `wsl.exe` w UTF-16LE** — `wsl -l -q` musi rozpoznać istniejącą dystrybucję `BPP` → test w Task 7.

### Task 4: `bpp-ctl` — polecenia i pobieranie z postępem

**Files:**
- Create: `distro/rootfs/opt/bpp/bin/bpp-ctl`, `lib/state.sh`, `lib/pull.sh`

**Interfaces:**
- Consumes: `emit`, `hosts_*`, `cert_generate`, compose z Task 3.
- Produces (kontrakt dla `BPP.Windows.WslClient`):
  - `bpp-ctl init --hosts <csv>`; `start --hosts <csv>`; `stop`; `status`; `logs [usługa]`.
  - stdout = wyłącznie linie JSON `emit`; ludzkie logi na stderr. Kod wyjścia ≠ 0 ⇔ ostatnie zdarzenie `error`.
  - `status` → jedna linia `{"running":bool,"health":"starting|healthy|unhealthy|absent"}` (zdrowie appservera).
  - `logs` → zwykły tekst `docker compose logs --tail 500 --no-color [usługa]`.
- Funkcje:
  - `state_ensure_env` — tworzy `state/.env` tylko jeśli nie istnieje: `DJANGO_BPP_DB_NAME=bpp`, `DJANGO_BPP_DB_USER=bpp`, `DJANGO_BPP_DB_PASSWORD=<openssl rand -hex 24>`, `DJANGO_BPP_DB_HOST=dbserver`, `DJANGO_BPP_DB_PORT=5432`, `DJANGO_BPP_REDIS_HOST=redis`, `DJANGO_BPP_REDIS_PORT=6379`, `DJANGO_BPP_REDIS_DB_BROKER=1`, `DJANGO_BPP_REDIS_DB_CELERY=2`, `DJANGO_BPP_SECRET_KEY=<openssl rand -hex 50>`, `STATIC_ROOT=/staticroot/`, `DJANGO_BPP_MEDIA_ROOT=/mediaroot`, `DJANGO_SETTINGS_MODULE=django_bpp.settings.production`, `DJANGO_BPP_SSL_MODE=manual`, `DJANGO_BPP_ADMIN_USERNAME=admin`, `DJANGO_BPP_ADMIN_EMAIL=admin@localhost`, `BPP_IMAGE_TAG=<z /opt/bpp/image-tag>`. Brakujące wymagane zmienne Django budujący sprawdza w `bpp/src/django_bpp/settings/base.py` (`env(...)` bez domyślnej).
  - `state_hosts_changed <csv>` → 0, gdy różni się od `state/hosts`.
  - `pull_with_progress` — dla każdego obrazu z `docker compose config --images` strumień `POST /images/create` przez `curl --unix-socket /var/run/docker.sock`; postęp = `(i + bajty_bieżące/bajty_łącznie_warstw_widzianych)/N`, emit co ≥1 s, krok `pull`. Fallback, gdy socket niedostępny (macOS w E2E): `docker pull` obraz po obrazie z postępem `i/N`.
- Przebieg `start`: `hwclock -s 2>/dev/null || true` → walidacja hostów → jeśli zmienione: `cert_generate`, `hosts_render_env > state/hosts.env`, zapis `state/hosts` → `docker compose up -d` → jeśli cert zmieniony i webserver już działał: `docker compose exec webserver nginx -s reload` → czekanie na `healthy` (emit `migrate` z `null`, limit 1800 s) → `ready`.
- `init` = `state_ensure_env` + `pull_with_progress` + `start`.

### Task 5: E2E stosu na macOS

**Files:**
- Create: `distro/tests/e2e.sh`

**Interfaces:**
- Consumes: `bpp-ctl` z Task 4 uruchamiane na hoście z `BPP_HOME=<kopia rootfs/opt/bpp w katalogu tymczasowym>`, `BPP_IMAGE_TAG=<tag>`.

Skrypt (bash, `set -euo pipefail`, sprząta `docker compose down -v` w `trap`):
1. `LAN=$(ipconfig getifaddr en0)`; `bpp-ctl init --hosts localhost,$LAN` → ostatnie zdarzenie `ready`.
2. `curl -sk -o /dev/null -w '%{redirect_url}' https://localhost:8443/` → zawiera `/setup/step/admin_user/` i zachowuje `:8443` albo jest względny.
3. GET formularza z cookie jar, wyciągnięcie `csrfmiddlewaretoken`, POST z `Origin: https://localhost:8443` i `Referer` → status 302 na `/setup/step/uczelnia/` (nazwy pól z `bpp/src/bpp_setup_wizard/`).
4. Na świeżej bazie (`down -v`, `init` ponownie) to samo przez `https://$LAN:8443` — POST bez błędu CSRF (403 = porażka).
5. `curl -skI https://localhost:8443/` → brak nagłówka `strict-transport-security`.
6. `docker compose ps -q` przed i po `bpp-ctl start --hosts localhost,$LAN` → identyczne ID kontenerów.

**Interfaces:**
- Consumes: `PayloadArchive` (wpisy `rootfs`, `BPP.exe`), `Preflight`, `WslClient`, `WindowsFeatures`, `Elevation`, `Registration`, `Ports`, `BppEvent`.
- Produces: `BPP-Setup.exe [--resume]`.

Okno: logo u góry, stały rozmiar ~560×420, strony: Powitanie → Postęp → Gotowe / Błąd.
- **Powitanie:** „Zainstaluj BPP (wersja testowa)”, zdanie o ~2 GB do pobrania i wymaganym internecie, przycisk „Zainstaluj”.
- **`InstallerFlow`** (kolejność ze specu 4.4):
  1. Preflight (`Ports` sprawdzane **przed** jakimkolwiek startem dystrybucji) → problemy jako lista po polsku na stronie Błąd.
  2. Wypakuj `BPP.exe` do `AppPaths.TrayExe`.
  3. WSL: `IsWslReadyAsync` false → jeśli `!IsWslFeatureEnabled` → `Elevation.Run(TrayExe,"--elevated","enable-wsl")`; odmowa → Błąd „Poproś administratora o włączenie WSL”; kod 3010 → `SetRunOnce("\"<ścieżka setup>\" --resume")` i strona „Uruchom ponownie komputer” (przycisk restartu: `shutdown /r /t 0`). Potem `InstallWslPackageAsync` jako zwykły użytkownik.
  4. `DistroExistsAsync` → pytanie „Zainstalować ponownie? Dane testowe zostaną usunięte.”; tak → `UnregisterAsync`.
  5. Wypakuj `rootfs` do `%TEMP%`, `ImportAsync`, usuń plik tymczasowy, `TrySetSparseAsync`.
  6. `RunCtlAsync("init --hosts …")` → pasek (`Progress` null → tryb marquee), etykieta = `Message`, rozwijane „Szczegóły” z pełnym logiem; zdarzenie `error` → strona Błąd z przyciskiem „Spróbuj ponownie” (ponawia od kroku 6).
  7. `Elevation.Run(TrayExe,"--elevated","firewall",TrayExe)`; odmowa → zapamiętaj `lanEnabled=false`.
  8. `CreateStartMenuShortcut`, `RegisterUninstall`, `ClearRunOnce`.
- **Gotowe:** „Otwórz BPP” (`https://localhost:8443/`), tekst o ostrzeżeniu certyfikatu („Zaawansowane → Przejdź do localhost”), przy `lanEnabled=false` zdanie „BPP jest dostępne tylko na tym komputerze”. Zamknięcie uruchamia `TrayExe`.
- `--resume` startuje od kroku 1 bez strony Powitanie.
